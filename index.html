// roadmap

成长路线 · Roadmap

完整概述
  1. Next 在建

    企业级大模型网关

    现状：接大模型的业务越来越多，算力开销只能事后对账，成本落不到具体团队；单一供应商限流或抖动直接拖停业务；接新模型要改一轮代码；调用记录分散，合规上无从追溯。

    要做的：调用收敛到统一入口，预算按组织、团队、个人逐级分配、花超即停；供应商故障自动切换，业务侧无感；接新模型走配置；每笔调用可追溯到人和场景。让大模型对业务方是一项成本可控、稳定可用、可审计的公共能力。

    统一入口预算硬约束成本可归属供应商无感切换换模型零改造调用可审计
  2. 2026 — 现在 当前 · 全栈开发

    转岗全栈，企业信息化系统

    岗位从测试开发转为全栈开发。转型的实证是一套内部平台从零做到线上：信息架构、界面交互、登录鉴权、前后端、数据建模、实时消息、异步任务编排、容器化部署和线上运维一个人做完，流水线侧打通自动构建、合入前冒烟拦截和发布通知。现在重心是企业信息化系统，和业务方一起把问题和流程定清楚，然后自己做出来、发上去、维护住。

    React / TypeScriptFastAPIJava / Spring BootMySQL / TairMQ · 配置中心 · 调度Docker · CI/CD
  3. 2021 — 2026 质量工程 · 深水区

    金融级稳定性与 AI 评测基建

    做支付宝基金与个人养老金的 QA Owner，负责测试策略、全链路压测、容灾演练、监控与应急预案，覆盖开户、缴存、资金链路和对账，负责期间零重大事故。之后转到实时语音方向，为同声传译建 WER 自动化评估和翻译基准集，用 LLM-as-a-Judge 做批量验证。这是我第一次系统地处理不确定输出，这套经验后来直接接到了大模型的工作上。

    全链路压测容灾演练资金链路WER 评测LLM-as-a-Judge
  4. 2016 — 2021 起步 · 测试开发

    自动化体系，第一次以开发身份交付

    从 SaaS 客服系统起步，补 Ruby on Rails 后端单测把覆盖率做到 80% 以上，用 Selenium / Appium 加 Jenkins 建端到端自动化，单次回归耗时降九成。之后在百度核心搜索做检索链路质量，写 Python / Shell 的 diff 工具接进 CI；中途转研发，做日历、天气垂类的业务开发和架构迁移，这是我第一次以开发身份交付业务。

    自动化体系覆盖率治理搜索链路diff 工具 · CI第一次转研发
