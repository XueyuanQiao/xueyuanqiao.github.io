### 五、对 AI 的持续学习与实战落地
对我而言，AI 不是一组工具的清单，而是 **一种持续重塑工作方式的学习习惯**。每天保留固定时间跟踪前沿（论文、X、产品发布、源码），并坚持一个朴素的原则——**任何新能力，必须在真实业务里跑通一次，才算"学过"**。

近一年的实践沉淀大致分三层：

- **学习与思考层**：用 **NotebookLM** 把论文、内部文档、长视频沉淀为可对话的知识库，把"读完即忘"的输入变成可复用的研究资产；新模型、新框架发布后，第一时间在小型真实场景里做 A/B 验证，再决定是否纳入工作流。
- **研发协同层**：日常以 **Kiro / Cursor / Claude Code / Codex / Antigravity** 等编程 Agent 作为主力副驾，按场景分工——架构演进与多文件重构走 Kiro 的 Spec 流程、复杂调试用 Claude Code 与 Codex 交叉验证、原型探索用 Antigravity 的浏览器化 Agent 完成端到端闭环；同时熟练运用 **Claude Code、Trae** 做 AI Coding，掌握提示词工程，能快速准确驱动 LLM 解决复杂问题。这套协同方式让我能在有限时间内推动多个项目并行演进。
- **Agent 学习层**：在"用 Agent"之外，也动手"拆 Agent"。为吃透框架原理，用 **LangChain** 写过一个支持 **GPT / Claude / Gemini** 多厂商动态路由的网页信息提取 demo——它本身没有实际业务价值，目的是把大模型分类、结构化提取、异常捕获与调试这套链路亲手跑通一遍；当前在用 **LangGraph** 搭一个学习性质的 AI 测试平台工程，借此摸清复杂智能体的循环控制、动态决策、多角色协作与长时记忆等机制。另外在阿里云 VPS 与本地完成 **OpenClaw** 部署、接入钉钉机器人做远程对话，理解其架构与运行原理。这些都还停留在学习与验证阶段，我不会把它们说成已落地的成果。
- **全栈交付层**：完整掌握 AI 时代的全栈开发链路——从用 **Stitch / Claude Design** 做产品与界面设计，到借助 **Vibe Coding** 把设计稿直接转化为前端与后端工程代码，独立完成"设计 → 前端 → 后端 → 联调 → 上线"的端到端闭环。菜鸟无人车质量中台正是这套方法的产物：一个人用 AI 把过去需要设计、前端、后端多角色协作的工作量收敛到一条流水线上，让"想得到"与"做得出"之间的距离大幅缩短。
- **业务落地层**：在 **腾展 AI Phone**（VOIP + ASR + 翻译 + TTS 全链路）的同声传译场景里，构建以 **WER 为核心指标** 的自动化评估 pipeline，并基于 **LLM-as-a-Judge** 设计翻译准确性的批量验证方案，用大模型替代易碎的硬编码 Diff，对海量译文做可复用、可回归的质量评估——这是我目前真正落到业务闭环的一次 AI 实践。在评测体系上，持续系统学习主流 Agent 评估框架（**Ragas / DeepEval / Langfuse / LangSmith**），并在实际业务中落地 **benchmark、LLM-as-a-Judge** 等智能化评测方法，推动测试流程向数据驱动与智能化演进。

我更看重的不是"用过多少工具"，而是 **是否真的在每个项目里因为 AI 而做出了过去做不到的事**——用更小的团队覆盖更大的质量域、用更短的周期完成更复杂的验证、把原本依赖经验的判断沉淀成可复用的资产。
