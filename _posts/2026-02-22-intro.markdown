## 个人总结

### 一、十年全栈质量治理积淀
深耕测试开发与质量工程领域十年，从 **百度大搜索** 起步，历经 **滴滴出行实时调度系统**、**蚂蚁集团金融级核心业务**、**菜鸟智能物流体系** 的连续淬炼，当前在 **九识智能** 专注于 L4 级无人配送车的端到端质量体系建设。覆盖 Web、客户端、服务端、数据链路、算法模型、车端嵌入式六大战场，沉淀出一套完整的 **白盒 / 灰盒 / 黑盒 + 静态 / 动态 / 模糊 / 混沌 + 仿真 / 路测** 全维度测试方法论，能够穿透业务表象、深度参与并驱动研发全生命周期的质量治理。

### 二、教育背景
- **2012 — 2016 · 北京科技大学（本科）· 计算机科学与技术**
  在科大计算机科学与技术专业打下系统的基础：数据结构与算法、操作系统、计算机网络、编译原理、数据库系统等核心课程，构建了从底层到应用的完整认知。这四年也给我留下了 **"啃硬骨头、拒绝糊弄"** 的工程师底色——习惯于把每个抽象概念落到代码里跑一遍才算理解，这种"动手验证"的方法论延续到了之后十年的测试与研发工作中，也是我今天面对 AI、自动驾驶等复杂系统时，仍然坚持"任何能力必须在真实场景里跑通一次才算学过"的源头。

### 三、职业履历 · 行业级业务的实战版图
- **百度（测试 → 研发）**：在大搜索体系下从测试工程师起步，深度参与亿级 PV 检索链路的质量保障，随后转型为研发，主导多个核心模块的架构演进与稳定性建设。这段经历奠定了 **以研发视角重塑质量底座** 的方法论根基，也让我能够同时用"产线视角"和"质量视角"看待同一个系统。
- **滴滴出行**：投身实时调度与出行核心链路的稳定性保障，面对 **海量并发、强地理时序、强一致性** 的复合挑战，建立起对高可用分布式系统、灰度与回滚机制、线上故障应急体系的系统性理解。
- **蚂蚁集团（支付宝）**：担任核心业务 **QA Owner**，主导 **个人养老金** 国家级战略项目的质量护航，并长期负责 **养老基金** 等核心金融业务的日常质量治理。在合规红线、资金安全、监管审计三重高压下，沉淀出覆盖资金链路、账户体系、对账与清结算的金融级质量保障方法论。
- **菜鸟**：进入智能物流与 AI 原生业务场景，将质量工程的边界从"Web / App / 服务端"延伸到 **算法模型、数据链路、IoT 与端侧智能**。在这里把 **LangChain / LangGraph 多 Agent 协同**、**LLM-as-a-Judge**、**RAG 智能测试助手** 等 AI 能力真正落到生产闭环，推动测试体系从"脚本驱动"走向"模型驱动"。
- **九识智能（当前）**：随菜鸟无人车业务合并加入九识，深入 **L4 级无人配送车** 这一最前沿的具身智能场景。质量保障的对象从"软件系统"扩展到"软件 + 硬件 + 物理世界"，开始系统性地探索 **仿真测试、路测验证、感知 / 规划 / 控制全链路质量、车云协同、OTA 灰度** 等自动驾驶领域的质量工程范式，把过往十年沉淀的测试架构方法论与 AI 能力，融入到无人车的端到端质量体系建设中。

### 四、跨职能技术架构视野（QA → RD → Test Architect）
具备从 QA 工程师向 RD 成功转型、再回归测试架构的复合背景。能够 **以研发视角重塑质量底座**，从底层架构层面剖析系统风险，而不是停留在功能验证。主导过亿级 PV / TPS 量级分布式系统的架构重构、数据链路优化与稳定性建设，在 **架构降本增效** 与 **故障可观测性建设** 上落地多个标杆案例，相关方法论沉淀为团队级的研发与质量规范。

### 五、对 AI 的持续学习与实战落地
对我而言，AI 不是一组工具的清单，而是 **一种持续重塑工作方式的学习习惯**。每天保留固定时间跟踪前沿（论文、X、产品发布、源码），并坚持一个朴素的原则——**任何新能力，必须在真实业务里跑通一次，才算"学过"**。

近一年的实践沉淀大致分三层：

- **学习与思考层**：用 **NotebookLM** 把论文、内部文档、长视频沉淀为可对话的知识库，把"读完即忘"的输入变成可复用的研究资产；新模型、新框架发布后，第一时间在小型真实场景里做 A/B 验证，再决定是否纳入生产。
- **研发协同层**：日常以 **Kiro / Cursor / Claude Code / Codex / Antigravity** 等编程 Agent 作为主力副驾，按场景分工——架构演进与多文件重构走 Kiro 的 Spec 流程、复杂调试用 Claude Code 与 Codex 交叉验证、原型探索用 Antigravity 的浏览器化 Agent 完成端到端闭环；这套协同方式让我能在有限时间内推动多个项目并行演进。
- **业务落地层**：在菜鸟智能物流以及当前九识无人车场景中，基于 **LangChain / LangGraph** 设计多 Agent 协同的测试系统，把"用例生成 → 执行 → 评估 → 缺陷归因"做成一条闭环；用 **LLM-as-a-Judge** 替代易碎的硬编码 Diff，让评估随业务语义自然演进；通过 RAG 把领域知识（含自动驾驶感知 / 规控的内部规范）注入智能测试助手，使新人 onboarding 与回归分析效率显著提升。

我更看重的不是"用过多少工具"，而是 **是否真的在每个项目里因为 AI 而做出了过去做不到的事**——用更小的团队覆盖更大的质量域、用更短的周期完成更复杂的验证、把原本依赖经验的判断沉淀成可复用的资产。

### 六、金融级高并发稳定性专家

### 七、测试架构设计与从 0 到 1 工程赋能
具备较强的技术落地与平台化建设直觉，多次主导从零搭建企业级测试平台——自动化框架、CI/CD 与质量门禁、全链路压测平台、缺陷分析与质量度量数仓——以技术手段解决业务稳定性痛点，让"质量"从人力堆叠转化为可复用的工程基础设施。坚持通过 **Code Review、技术分享、内训体系** 驱动团队整体效能跨越式增长，培养出多名核心技术骨干。

### 中间件与分布式深度能力
长期在金融级与高并发场景下与中间件打交道，熟悉其内部机制与典型故障模式，能在生产链路上做端到端定位：

- **缓存与存储**：Redis 主从 / 集群 / 哨兵的容量与热点治理，蚂蚁自研 **Tair** 在金融级场景下的高可用与一致性实战
- **消息中间件**：**RocketMQ**（蚂蚁 / 阿里体系）、Kafka、RabbitMQ 的顺序、堆积、重试、死信与一致性问题排查
- **RPC 与服务治理**：**Dubbo / SOFARPC / SOFABoot** 等蚂蚁金融级中间件与微服务架构，熟悉路由、限流、熔断、灰度的稳定性建设
- **配置与注册中心**：**Apollo / Nacos / ZooKeeper** 的多环境配置治理、动态推送与变更风险防控
- **JVM 深度排查**：**Java coredump / hs_err / heap dump** 分析，结合 Arthas、JFR、async-profiler 做 CPU 飙高、Full GC、线程死锁、Native Crash 等线上问题的根因定位
- **Linux 与系统层**：熟练掌握常用命令链与性能工具（top / vmstat / iostat / perf / strace / tcpdump / ss），具备从内核态到用户态的链路诊断能力
