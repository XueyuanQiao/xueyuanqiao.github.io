# 站内音乐播放器维护文档

本文记录站内播放器的加载、自动播放、连续播放和缓存策略。目标不是尽快出声，而是在弱网下优先避免反复缓冲造成的断续体验。

## 1. 页面链路

- 根路径 `/` 是独立宇宙页。它不播放音乐，只用隐藏的原生 `<audio preload="auto">` 低优先级预热播放列表第一首。
- `/blog/` 是博客主页。进入后复用同源 HTTP 媒体缓存，继续加载同一个音频 URL。
- 博客内部使用 PJAX，播放器节点不会随正文替换，因此播放位置、缓冲和音频实例可跨文章连续保留。

宇宙页与博客页是两个独立文档，不能共享同一个 `HTMLAudioElement`。预热的交接依赖浏览器对同源媒体请求的 HTTP 缓存复用；博客页仍以自身 `audio.buffered` 为最终安全依据，不能盲信宇宙页记录的数据。

## 2. 自动播放原则

博客主页初次进入时会自动准备并尝试播放。用户主动暂停后，会在当前标签页的 `sessionStorage` 中记录该意图，刷新或再次进入主页时不擅自恢复。若上一页本来正在播放，则按已保存的曲目与时间继续。

有声自动播放最终受浏览器策略控制，代码必须检查 `audio.play()` 返回的 Promise：

- 允许时直接开始。
- 返回 `NotAllowedError` 时显示“已缓冲 · 点击播放”，不伪装成播放中，也不报普通加载错误。
- 浏览器拦截后，用户下一次点击页面或播放器按钮会立即重试已准备好的音频。

## 3. 自适应安全缓冲

播放器不等待整首文件下载完成。它综合以下信号决定何时开始出声：

1. `canplaythrough` 或 `readyState === HAVE_ENOUGH_DATA`：浏览器判断按当前下载速度可连续播放。
2. `audio.buffered`：当前播放点之后已有多少秒可用音频。
3. 缓冲增长速度：用约 9 秒滑动窗口估算“每秒新增多少秒音频”。增长速度越快，所需起播水位越低。
4. `navigator.connection.effectiveType` 与 `saveData`：仅用于没有足够实测样本时设置更保守的初始水位。

部分浏览器在暂停状态只公开约 4–6 秒 `buffered`，即使后台下载仍在继续。此时如果浏览器已经给出 `HAVE_ENOUGH_DATA / canplaythrough`，播放器会先进行无声的原生媒体预热，让下载与解码继续推进；达到自适应水位后把时间重置到起点，再切换为有声播放。若浏览器不允许延迟取消静音，则停在“已缓冲 · 点击播放”，等待下一次明确的用户操作，不会先响一小段再停。

当前安全水位大致为：

| 条件 | 起播缓冲目标 |
| --- | ---: |
| 缓冲速度 ≥ 播放速度 3 倍 | 12 秒 |
| 1.8–3 倍 | 18 秒 |
| 1.3–1.8 倍 | 至少 28 秒 |
| 1.1–1.3 倍 | 至少 42 秒 |
| 低于播放速度 | 60 秒以上，或等待浏览器确认可连续播放 |

若播放中仍因网络突变触发 `waiting`，播放器会转为一次受控的“稳定缓冲”，把恢复水位额外提高 12 秒后再继续，避免短暂恢复后再次反复卡顿。

## 4. 缓存与带宽竞争

Service Worker 的 Cache Storage 只能持久化完整响应。为了避免完整缓存请求与正在播放的媒体流争抢带宽，播放器仅在浏览器已经缓冲约 97% 曲目时才请求持久化，不会在刚有 30 秒缓冲时另起整曲下载。

播放优先级如下：

1. 当前曲目的安全缓冲。
2. 当前曲目持续播放。
3. 接近完整后再做持久缓存。

不要在当前曲目尚未稳定时并行完整下载整个播放列表。

## 5. 状态与文案

- `.is-buffering`：正在建立安全缓冲或无声预热；播放按钮显示可取消的暂停形态。
- `.is-playing`：原生音频已真正开始播放。
- `.is-resume-pending`：音频已准备好，但浏览器要求用户交互。
- `data-cache-state="buffering"`：详情区显示当前缓冲秒数与目标秒数。

播放器不能仅凭调用 `play()` 就切换为播放态，必须等待真实 `play` 事件。

## 6. 验证清单

基础检查：

```bash
node --check assets/js/particle-cat.js
node --check assets/js/site.js
git diff --check
bundle exec jekyll build
```

浏览器检查：

- 打开 `/` 后，隐藏预热音频存在且 `currentSrc` 指向第一首，页面没有声音。
- 从宇宙页进入 `/blog/` 后，播放器先显示安全缓冲，再自动尝试播放。
- 起播时 `audio.readyState >= 3`，且 `buffered` 达到安全判定条件。
- 自动播放被拒绝时显示“已缓冲 · 点击播放”，下一次用户点击能开始。
- 用户主动暂停后刷新 `/blog/` 不会擅自播放。
- 播放中进入文章，`currentTime` 连续增长，音频元素不被重建。
- 控制台没有未处理的 Promise、媒体加载或 Service Worker 错误。
