# 站内音乐播放器维护文档

本文记录站内播放器的加载、自动播放、连续播放和缓存策略。目标不是尽快出声，而是在弱网下优先避免反复缓冲造成的断续体验。

## 1. 页面链路

- 根路径 `/` 是独立宇宙页。页面只用隐藏的原生 `<audio preload="auto">` 低优先级预热第一首，停留和跃迁过程始终无声。
- `/blog/` 是博客主页。进入后复用同源 HTTP 媒体缓存，继续加载同一个音频 URL。
- 博客内部使用 PJAX，播放器节点不会随正文替换，因此播放位置、缓冲和音频实例可跨文章连续保留。

用户点击宇宙页的博客入口时，入口事件只确保预热已启动并写入跨页播放意图，不调用 `audio.play()`。博客页必须等浏览器标准 `window.load` 完成，并再让出两个渲染帧，才开始安全缓冲和自动播放流程，避免音频解码、可视化与页面加载收尾争抢主线程。

宇宙页与博客页是两个独立文档，不能共享同一个 `HTMLAudioElement`。预热的交接依赖浏览器对同源媒体请求的 HTTP 缓存复用；博客页仍以自身 `audio.buffered` 为最终安全依据，不能盲信宇宙页记录的数据。

## 2. 自动播放原则

博客主页初次进入时会在整页加载完成后自动准备并尝试播放。用户主动暂停后，会在当前标签页的 `sessionStorage` 中记录该意图，刷新或再次进入主页时不擅自恢复。若上一页本来正在播放，则在新文档加载完成后按已保存的曲目与时间继续。

首次直接打开 `/blog/` 或从宇宙页进入时，浏览器仍可能禁止有声自动播放；网页不能绕过这一安全策略。被拦截时播放器会等待下一次明确的用户操作，再播放已经缓冲好的音频。

有声自动播放最终受浏览器策略控制，代码必须检查 `audio.play()` 返回的 Promise：

- 允许时直接开始。
- 返回 `NotAllowedError` 时显示“已缓冲 · 点击播放”，不伪装成播放中，也不报普通加载错误。
- 浏览器拦截后，用户下一次点击页面或播放器按钮会立即重试已准备好的音频。

## 3. 自适应安全缓冲

播放器不等待整首文件下载完成。它综合以下信号决定何时开始出声：

1. `canplaythrough` 或 `readyState === HAVE_ENOUGH_DATA`：浏览器判断按当前下载速度可连续播放。
2. `audio.buffered`：当前播放点之后已有多少秒可用音频。
3. 缓冲增长速度：用约 9 秒滑动窗口估算“每秒新增多少秒音频”。增长速度越快，所需起播水位越低。
4. `navigator.connection.effectiveType` 与 `saveData`：仅用于没有足够实测样本时设置更保守的初始水位。

部分浏览器在暂停状态只公开约 4–6 秒 `buffered`，即使后台下载仍在继续。此时如果浏览器已经给出 `HAVE_ENOUGH_DATA / canplaythrough`，播放器会先进行无声的原生媒体预热，让下载与解码继续推进；达到自适应水位后把时间重置到起点，再切换为有声播放。若浏览器不允许延迟取消静音，则停在“已缓冲 · 点击播放”，等待下一次明确的用户操作，不会先响一小段再停。

当前安全水位大致为：

| 条件 | 起播缓冲目标 |
| --- | ---: |
| 缓冲速度 ≥ 播放速度 3 倍 | 12 秒 |
| 1.8–3 倍 | 18 秒 |
| 1.3–1.8 倍 | 至少 28 秒 |
| 1.1–1.3 倍 | 至少 42 秒 |
| 低于播放速度 | 60 秒以上，或等待浏览器确认可连续播放 |

若播放中仍因网络突变触发 `waiting`，播放器会转为一次受控的“稳定缓冲”，把恢复水位额外提高 12 秒后再继续，避免短暂恢复后再次反复卡顿。

## 4. 缓存与带宽竞争

Service Worker 的 Cache Storage 只能持久化完整响应。为了避免完整缓存请求与正在播放的媒体流争抢带宽，播放器仅在浏览器已经缓冲约 97% 曲目时才请求持久化，不会在刚有 30 秒缓冲时另起整曲下载。

播放优先级如下：

1. 当前曲目的安全缓冲。
2. 当前曲目持续播放。
3. 接近完整后再做持久缓存。

不要在当前曲目尚未稳定时并行完整下载整个播放列表。

## 5. 状态与文案

- `.is-buffering`：正在建立安全缓冲或无声预热；播放按钮显示可取消的暂停形态。
- `.is-playing`：原生音频已真正开始播放。
- `.is-resume-pending`：音频已准备好，但浏览器要求用户交互。
- `data-cache-state="buffering"`：详情区显示当前缓冲秒数与目标秒数。

播放器不能仅凭调用 `play()` 就切换为播放态，必须等待真实 `play` 事件。

## 6. 界面与占位

- 播放器默认展开，常驻层级只保留曲名 / 状态、上一首 / 播放 / 下一首、进度、歌单、音量和收起操作。网易云、QQ 音乐入口继续由侧栏和音乐内容区承载，不在播放器内重复展示。
- 普通状态的副标题显示歌手 `xueyuan`；缓冲、恢复或自动播放受限时复用这一位置显示简短状态。缓存实现文案只通过 `aria-live` 提供给辅助技术，不作为常驻界面信息。
- 桌面端音量滑杆在悬停或键盘聚焦时展开，移动端保留静音按钮，减少有限空间内的常驻控件。
- 博客内部 PJAX 换页保留当前展开或收起状态，不重建播放器，也不打断播放。
- 播放列表按顺序自动播放一次：前两首自然结束后继续下一首，最后一首结束后切回第一首并停止。此时再次点击播放会从第一首开头重新开始，手动切歌仍可自由选择。
- 新会话默认停在右下角展开显示；用户明确保存过的拖拽或贴边位置仍优先恢复。
- 移动端和桌面端都要为展开态预留足够的页尾空间，避免正文末尾与回到顶部按钮被遮挡。
- 拖拽位置使用 v5 本地键保存，旧版异常位置不会继续沿用。

展开、收起、歌单和贴边切换使用可取消的 FLIP 动画：DOM 只切换一次最终布局，视觉过程由合成层 `transform` 完成。连续点击会取消上一段动画并从当前视觉位置继续，不使用固定时长的延迟校正。歌单切换时对头部和进度区使用多关键帧的倒数缩放补偿，避免背景高度变化把控件纵向拉伸。

动画期间暂停频谱绘制并隐藏高成本装饰，结束后只更新一次 Canvas 内部尺寸；窗口尺寸变化若撞上布局动画，会延后到动画稳定后再重建画布。播放进度最多约 12.5 FPS 更新，可视化最多约 30 FPS；播放器收起、贴边、页面隐藏、没有 analyser 或启用减少动态效果时不持续重画静态波形。运行中切换系统“减少动态效果”也会立即取消当前动画并落到最终状态。

桌面普通态拖拽在 `pointermove` 中只记录目标坐标，通过单个 `requestAnimationFrame` 写入 `translate3d`，松手后才提交 `left/top` 和持久化位置。贴边收起态在桌面和触屏均可拖动：纵向手势锁定当前侧，明显横向手势允许保持紧凑形态跨屏，松手后只吸附到最近的左侧或右侧，不进入浮动展开态。按钮采用移动阈值区分点击与拖拽，真实拖动后会抑制该次点击，避免误触播放或展开。

贴边位置按贴边后的真实尺寸和可视视口归一化保存与恢复，四边边界统一计入 `safe-area-inset-*`；从贴边态展开后的自由位置也沿用同一套安全区计算，避免跨断点、横屏刘海或底部 Home Indicator 下发生偏移与遮挡。聚焦贴边展开按钮时，还可用方向键上下移动或切换左右侧，`Home / End` 直接移动到顶部 / 底部，`Shift + ↑ / ↓` 使用更大步长；落位结果通过 `aria-live` 播报。

## 7. 验证清单

基础检查：

```bash
node --check assets/js/particle-cat.js
node --check assets/js/site.js
git diff --check
bundle exec jekyll build
```

浏览器检查：

- 打开 `/` 后，隐藏预热音频存在且 `currentSrc` 指向第一首，页面没有声音。
- 点击博客入口后的跃迁过程保持无声。
- 从宇宙页进入 `/blog/` 后，`document.readyState` 到达 `complete` 之前音频保持暂停；随后播放器才显示安全缓冲并自动尝试播放。
- 起播时 `audio.readyState >= 3`，且 `buffered` 达到安全判定条件。
- 自动播放被拒绝时显示“已缓冲 · 点击播放”，下一次用户点击能开始。
- 用户主动暂停后刷新 `/blog/` 不会擅自播放。
- 播放中进入文章，`currentTime` 连续增长，音频元素不被重建。
- 从第一首连续播放到第三首结束后保持暂停，当前曲目回到第一首且进度为 `0:00`；刷新或 PJAX 换页后仍停在第一首，再次播放从头开始。
- 播放器首帧默认展开，PJAX 换页不会覆盖用户当前的展开或收起状态。
- 在暂停和播放两种状态下连续快速展开 / 收起 8–10 次，结束后不应残留 `is-layout-transitioning`，也不能出现迟到的位移或尺寸跳变。
- 展开歌单后直接收起播放器，歌单状态应同步关闭；再次展开时回到精简主界面。
- 桌面拖拽、靠边吸附、贴边展开和双击归位均保持位置连续；375px 手机宽度下收起态不遮挡正文主操作。
- 贴边收起态从播放按钮、空白区和展开按钮起拖均可上下移动；横向拖过屏幕中线后能切到另一侧，松手后始终保留 `is-collapsed is-edge-docked`，且拖动不会误触播放或展开。
- 贴边位置在刷新和 PJAX 换页后保持；桌面切到 375px 手机宽度后仍可纵向拖动和跨侧吸附，并受顶部 / 底部安全边距约束。
- 聚焦贴边展开按钮时，方向键、`Home / End` 和带 `Shift` 的大步长移动可用，左右圆角、箭头方向和位置播报与最终侧边一致。
- 键盘遍历播放、歌单、收起和贴边按钮时，焦点环完整可见；移动端收起态的播放与展开按钮均保留完整触控区域。
- 展开歌单时头部和进度区保持正常比例；运行中开启“减少动态效果”会立即结束当前动效，后续切换不再创建动画。
- 展开 / 收起期间 Canvas 不连续重设 backing store，收起和贴边状态不持续绘制频谱。
- 控制台没有未处理的 Promise、媒体加载或 Service Worker 错误。
